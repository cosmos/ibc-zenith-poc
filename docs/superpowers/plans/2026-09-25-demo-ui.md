# Demo UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A presenter-driven browser UI that animates an IBC transfer between Besu and Zenith, from scripted data or from a live run of the PoC.

**Architecture:** Pure TypeScript core (journeys → engine → scene) turns checkpoint events into a
visual `Scene`; a thin DOM layer renders it into the SVG from the approved mockup. Checkpoints come
from a scripted table or from a no-dependency Node server that runs the `ibc` CLI and streams events
over SSE.

**Tech Stack:** Vite, TypeScript, Vitest, inline SVG; Node 24 (`node:http`, `child_process`).

**Spec:** `docs/superpowers/specs/2026-09-25-demo-ui-design.md` · mockup `docs/superpowers/specs/demo-ui-mockup/`

## Global Constraints

- Canvas 1920×1080, scaled to fit the window; dark theme; Besu `#ff9f43`, Zenith `#34e0c4`, packet `#a48bff`.
- No on-screen controls: `Space`/`→` next, `←` back, `R` restart, `1`/`2` journey (at ready), `S` fall back to scripted (live).
- Three attestors drawn per chain; PoC config untouched; no attestor count or threshold shown.
- Scripted mode shows only real values from RESULTS.md and the local keystore; no invented hashes or heights.
- Live server port 3200 (3000 and 3100 are taken); it never starts chains or the relayer.
- Forward sends 10 ZPOC, return sends 2 ZPOC, client `link-41003-936485`.

## Review Focus

1. Presenter mashes `Space` while waiting on a live checkpoint → exactly one advance when it arrives. (Task 2 test)
2. A live packet that times out → the UI never shows "minted"; it stops with an amber error. (Task 2 test)
3. A second `POST /api/transfer` while one runs → 409, never a second burn on camera. (Task 7 test)
4. `ibc` output with warning noise, or a CLI failure (the env.sh wrapper always exits 0) → parsed or reported as an error checkpoint, never a hung run. (Task 6 test)
5. Page reload or late SSE connect mid-run → the current run's checkpoints are replayed. (Task 7 test)
